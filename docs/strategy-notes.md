# ag 策略说明

这张图只表达判断，不代表系统状态。点的位置说明一个策略的期望收益和副作用，不说明它已经实现。所有策略均已写入策略目录；是否可拔由 `ag plug list` 显示，具体 handler 是否存在以源码为准。

## 坐标

- 横轴：真实帮助。越右，越能在真实交付中救回错误。
- 纵轴：副作用。越上，越容易制造流程税、假拦截或新的治理病。
- 虚线右下：正面作用大于负面作用，值得保留或试验。
- 绿：该类该用。黄：建议/体检。蓝：看见，不当门。

## Ship · 交货

1. **流程≠产品**：每次 status / finish 都分开写 `process` 和 `product`。没登记测试命令，产品永远是 `undeclared`，流程照样可以走完。
2. **worktree 工地**：start 在 `~/.ag` 里开一个 git worktree，只许在那里改文件。主仓不是工地。
3. **Git hook 拒 canonical**：入学时装上 git pre-commit。主仓 commit 一律拒绝，并记一次拦截。
4. **只有 finish 能 commit**：worktree commit 必须带 `AG_DELIVER=1`，只有 finish 会设置这个变量。
5. **ff-only 放行**：finish 用 `git merge --ff-only` 合入主仓；主仓已前移则失败，不覆盖历史。
6. **工程测试**：入学登记测试命令，verify 在工地执行；未登记就是 `undeclared`。
7. **树钉 digest**：verify 记录 worktree 树哈希，finish 重算；不一致则拒绝。
8. **危房/脏报**：hook 掉了或 canonical 脏了，start/finish 拒绝。
9. **金丝雀**：入学后立刻试两次空 commit，都必须失败并提到 canonical，否则回滚入学。
10. **转发旧 hook**：保留并转发原有 hooksPath，避免 ag 覆盖 husky 等旧门禁。
11. **unenroll 可逆**：有退出机制，去掉 ag hook 并恢复原 hooksPath；未完结任务先 abandon。

## Heal · 治病

1. **列门**：人先怀疑叠门再手动运行；只读 CSS `@import`、JS barrel、Python re-export，清单写 `~/.ag`。近期实战发现它漏看一类常见症状：多个 CSS 文件重复决定同一视觉状态（如同名 selector 各写一份）。后续可把“同名 CSS selector 分布”纳入 `heal-1` 扫描面。
2. **一案一刀**：从抢门清单挑一条，交给 ship 的 worktree 开工；heal 只提议，不合入、不拒 finish。
3. **案卷过期**：清单带时限，过期重列；不做永远清不完的施工队列。
4. **仓外正身针**：对抢门文件在 `~/.ag` 记哈希，不写业务代码，不自动插针。
5. **门诊判定**：输入症状账和所有权表，输出噪音 / 事故 / 风险 / 疑似 / 确诊；判据是不变量、跨意图复发、多所有者、修复轨迹加层。
6. **一刀处方**：为确诊病写一张治疗工单：保留哪个正身、删除哪扇门、术后观测什么；不自动执行，交给 ship。

## Lift · 抬正确率

1. **仓内复用搜索**：先找仓库已有函数、文件和相似实现，避免再造一份漂移的新代码。
2. **仓库已有检查当建议**：发现 ruff、pyright 等检具则执行，结果只是 advice，不签发交货绿。
3. **画像回声**：开工时写“做完长什么样”，验收时重读并对照工地 diff。
4. **LLM 审核当建议**：另请一个模型只找错，输出 advice；缺席只少一条意见，不阻塞交付。
5. **档案室 git log**：对 touched files 查历史，尊重已有代码的形成原因。
6. **店里已有的检具**：找到已引用或点名 touched files 的测试，建议先看、先跑，不改交货命令。
7. **上次考卷**：把上次 verify 失败输出带回下一轮，避免重复栽同一坑。
8. **同名已存在**：新建函数、文件、目录前查同名，防止两套同名物并存。
9. **反例建议**：构造应当失败的例子作为建议，不自动写入仓库测试。
10. **用一句话说 diff**：把工地 diff 压成一句话，对照开工画像，发现跑题和无关改动。
11. **四眼原则**：可选第二只眼睛只找错，不能拒绝交货；缺席不是事故，裁决仍在交货链。
12. **意图锚点**：用户脑内常有 A→B→C，但嘴上只说 C。意图锚点把 A、B 显式化成多个注意力点，让模型持续靠近而不是逐步执行。锚点不是计划，不是验收标准，不挡 finish；它让 AI 在用户建议偏离锚点时敢于反驳。
13. **有变才说**：没有新信息，就不重复提醒。只在画像、touched files、tree digest、probe 或 verify 结果变化时触发相应建议，保持信号强度，不让 lift 变成背景噪音。
14. **工地便签**：当前任务内保留原始观测便签，例如工具输出、失败片段、probe 结果；不记录 AI 自述，不跨任务，不进产品树，不作为证据，不挡 finish，任务结束即丢弃。

## See · 看见

1. **项次帮助/拦截账**：每项使用记 `help` 或 `block`，`ag usage` 读取；这是使用账，不是覆盖率。
2. **未登记区清单**：列出入学测试命令很可能没碰到的文件；是清单，不是百分数，不当门。
3. **在途 diff**：列出当前 worktree 改了哪些文件，区分后厨与橱窗。
4. **最近拦截**：交货失败时列出最近 block，先查脏仓、hook、digest。
5. **三行简报**：status/start 附仓脏、hook、从未使用项和上次拦截，控制注意力成本。
6. **橱窗对后仓**：对照主仓上次 product 与 worktree 未交货 diff，防止施工被说成上架。
7. **认哪一座城**：列出已入学仓的真实路径与编号，junction 算同一座。
8. **未测绘区在长大吗**：比较未登记文件数量变化，只看趋势，不自动清算。
9. **交接链**：查文件最后一次随 ag finish 进入主仓的提交，用 git 证据代替责任人卡片。
10. **症状账**：按 loop 记录意图外效应、locator、证据和 co-change；只记账，不诊断，不挡门。
11. **所有权表**：对被点名的症状列出定义者、修改者、覆盖者和消费者；只列事实，不判病。

## 治病入口重构

1. **病人是不变量，不是文件**：先说出“哪句话被违反”，例如“页面背景只能由 theme 层决定”。
2. **症状是意图外效应**：本轮没想做、却发生了的行为变化，才算症状；一次只能算 incident。
3. **复发看跨意图**：不同意图反复破坏同一不变量，才比同一 bug 重修更像病。
4. **所有权看谁能决定**：定义者、修改者、覆盖者、消费者分开列；多消费者不等于多所有者。
5. **修复轨迹看收敛还是扩散**：每次修复都加一层，就是病在加重；删除入口才算治疗。
6. **确诊五闸**：可命名不变量、跨意图复发、多所有者、不同入口触发、修复轨迹加层；全过才确诊。
7. **分工不变**：see 记症状和所有权，heal 判病和开处方，ship 动刀；heal 不自动 start，不挡 finish。

## 意图锚点的边界

- **它是注意力，不是步骤**：锚点允许模型保持连贯思考，在附近选择更好路径。
- **它允许多点共存**：锚点可以有多个，也可分主次，但不应膨胀成大清单。
- **它不要求完美**：无法精确满足某个锚点时，应披露偏离，而不是卡死。
- **默认是软约束**：只有用户话术或既有规则里存在明确的“必须”“禁止”“不要”时，AI 才能把锚点标成硬锚点；AI 可以建议升级，但不能把自己的猜测升成硬标准。
- **它增强拒绝力**：如果用户后续建议明显偏离既有锚点，AI 应先说明冲突，再行动。
